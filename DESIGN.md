# Design System: Diagrams

## Overview

**Creative North Star: "The Signal on Black"**

Pure black ground (white in light), chrome one step above, grey structure, one moving blue signal; four protocol hues
only on wires.

**Key Characteristics:**

- Right-angled, rounded edge routing by default.
- Docked chrome on a 44 px bar; panels on demand.
- Live, read-only canvas previews, never static wireframes.
- Boundary tier: line pattern first, hue second.

## Colors

### Primary

- **Signal Blue** (signal): walkthrough on edges without a protocol; token dot and chip before the first protocol hop;
  active node ring; active and hovered boundary outline (2 px); active log dot; caption step badge; library stage header
  flow dot; focus outline; caret; selection tint (34% mix); token in the app mark and favicon.
- **Signal Ink** (signal-ink): text on Signal Blue; white in both themes, black in the dark high-contrast canvas.

### Secondary

Protocol palette. Each protocol has a wire value (line, arrowhead), a brighter text value (label, traffic, token) and
`-light` keys. Edge `protocol`: HTTP, RPC, database, messaging or `auto` (from the label). Diagram switch "protocol
colours" off: all wires neutral edge grey.

- **Lime** (wire-http, wire-text-http): HTTP, REST, GraphQL, WebSocket, OAuth.
- **Teal** (wire-rpc, wire-text-rpc): gRPC, tRPC, Thrift, SOAP.
- **Violet** (wire-data, wire-text-data): SQL, queries, caches, replication.
- **Pink** (wire-messaging, wire-text-messaging): publish, consume, queues, streams, events.
- **Wire Ink** (wire-ink): text on a protocol-coloured token chip; black in dark, white in light.

### Tertiary

- **State colours** (ok, warn, error): ok and warn status markers; warn and error event levels in log and caption;
  destructive actions. Info events: plain text colour.
- **Boundary palette** (zone-orange, zone-yellow, zone-green, zone-teal, zone-blue, zone-pink, zone-red): boundary
  outlines, label icons, kind tags. Kinds set a default hue; users can pick another or Neutral (Strong Line).
  Coloured cards and shapes share these hues (one team hue on boundary and nodes). Zone Blue is a pale steel, never
  read as the signal.

### Neutral

- **Ground** (ground): page and canvas floor; knockout behind edge labels, boundary labels, tokens, ports; external and
  idle node fill; featured stage.
- **Chrome** (chrome): top bar, log pane, properties panel, library cards, caption strip.
- **Raised** (raised): popovers, menus, active log row.
- **Node Fill** (node-fill): card and shape fill; secondary button fill.
- **Node Fill Active** (node-fill-active): active or hovered node.
- **Hairline** (hairline): every 1 px border and divider in app chrome.
- **Node Line** (node-line): node outlines, idle edges in a flow, input borders.
- **Strong Line** (line-strong): dashed external outlines, neutral boundary outlines, handle borders, queue ribs.
- **Edge** (edge) and **Edge Strong** (edge-strong): default edge stroke and arrowheads, meter fill, ports.
- **Grid Dot** (grid-dot) and **Grid Dot Active** (grid-dot-active): canvas dot grid; brighter while a node is dragged.
  **Grid Line** (grid-line): Lines background.
- **Canvas Raised** (canvas-raised): datastore caps, client title strip, queue end caps, badges, meter track; lighter
  than Raised, as it sits on Node Fill.
- **Dim Line** (line-dim): idle node outline in a flow.
- **Particle** (particle): edge traffic particles.
- **Text** (text): primary text, primary button fill, dashed selection outline.
- **Muted** (muted): secondary text, node detail lines, edge labels, pending log lines, icons.
- **Faint** (faint): idle node text in a flow, least important metadata.

### High contrast

Per viewer, not per diagram: Contrast (System, Standard, High) on the App tab of Settings; "High contrast canvas" in
the library theme and command menus. System follows the OS "more contrast" setting. On-screen canvases and colour
swatches only; exports keep standard colours. Values: `[data-contrast='more']` in `src/styles/canvas.css`.

- Text colours: 7:1 (WCAG AAA) on Ground, Node Fill, Canvas Raised, coloured cards (standard 4.5:1).
- Node Line, Strong Line, Edge, Edge Strong, Signal Blue, protocol wires, coloured card outlines: 4.5:1 on Ground and
  Node Fill. Dim Line: 3:1, so idle flow nodes still show.
- Node Fill moves closer to Ground; outlines separate nodes.
- Same hues; light values at lower OKLCH lightness. Dark: Signal Blue lighter (#5e97ff), Signal Ink black.
- Dimmed opacity (standard in parentheses): nodes outside the explored neighbourhood 45% (16%); threat view connections
  without sensitive data 50% (25%); idle node art in a flow 70% (40%).
- `src/styles/contrast.browser.test.ts` checks every pair, both themes, both contrasts.

### Named Rules

**The One Signal Rule.** Signal Blue: walkthrough or keyboard only; never a button, link, badge, chart, node kind or
boundary style. Neither boundary nor protocol palette has a saturated blue.

**The Protocol Owns the Wire Rule.** A protocol hue colours only its wire: line, arrowhead, traffic, label, and the
token on or just off that wire. Visited and active edges: 2 px, protocol text colour. HTTP is lime, not amber, so it
never reads as warn.

**The State Only Rule.** Ok, warn and error only for levels and statuses; never decoration or node kinds.

**The Two Themes, One Structure Rule.** Each dark token has a same-role light counterpart; light mirrors dark on white.

## Typography

**Display Font:** Host Grotesk Variable (with ui-sans-serif, system-ui)
**Body Font:** Host Grotesk Variable (with ui-sans-serif, system-ui)
**Label/Mono Font:** Fragment Mono (with ui-monospace), slashed zero and tabular figures

**Character:** Two-weight grotesque, tighter as it grows; narrow mono for values people paste.

Canvases default to the `host` pair; a diagram can switch to Atkinson Hyperlegible, Inter with JetBrains Mono, or IBM
Plex. Chrome stays on Host Grotesk.

### Hierarchy

- **Display** (500, 48px, 36px below 640px, 1.04, -0.03em, balanced wrap): first-run library headline.
- **Section display** (500, 36px, 30px below 640px, 1.1, -0.03em, balanced wrap): first-run "What you can do", so
  features read as their own chapter under the stage.
- **Headline** (500, 24px, -0.02em): returning library "Your diagrams".
- **Title** (500, 20px, -0.015em): library section headings.
- **Card name** (500, 15px, -0.01em): library card names; wordmark at -0.02em.
- **Body** (400–500, 14px, 20px line): buttons, menus, panel text. Support copy under the display: 16px muted.
- **Caption** (400, 15px, 22px line): caption strip; pretty wrap, max 72px tall.
- **Node title** (500, 13px, 18px line): canvas card titles, shape labels.
- **Label** (400, 12–13px): field labels, card meta lines, log element and caption columns (13px sans).
- **Canvas text lg and xl** (500, 20/26 at -0.015em and 28/32 at -0.03em): canvas titles and notes. Small, medium:
  12/17, 14/21 at 400.
- **Mono** (400, 12px): log rows, offsets, latencies, caption step and event.
- **Mono label** (400, 11–11.5px): edge labels, token chip, card badges, meter text, boundary detail, identifier card
  lines.

### Named Rules

**The Copyable Value Rule.** Hosts, paths, address ranges, ports, offsets, events and edge labels use Fragment Mono.
Card detail lines use mono only as identifiers (no spaces and a non-letter, a path, or a port); prose like "Go, 3
replicas" stays sans.

**The Tight From Twenty Rule.** From 20px: weight 500, negative tracking (-0.015em at 20px, -0.03em from 28px). Never
above 500.

**The Sentence Case Rule.** Sentence case, plain words. No uppercase labels or letter-spaced headings.

## Layout

- **Top bar:** 44px, chrome fill, hairline below; side padding 6px (editor, Present), 12px (library). Library: mark,
  wordmark, agent button (desktop only), GitHub link, theme, Import (ghost), New diagram (primary).
- **Library, first run:** centred column, max 1152px.
  - Headline and support line; agent introduction beside them from 1280px (384px column, bottom-aligned; offer on top,
    stage above the fold), else under.
  - Full-width stage, 16px corners: window height less 360px, clamped 360–620px, so stage and caption strip fit
    1280×720. Loops the Order system flow with captions.
  - Features 80px under the stage.
  - Other templates as live cards under "More templates", two per row from 640px.
  - Install offer on tablets.
- **Library, returning:** agent introduction; "Your diagrams" with count and 256px search; 1–3 column card grid;
  storage line; live template cards (1–3 columns) under "Templates" with the first-run hint.
- **Previews:** read-only 16:10 canvases, no grid.
  - Cards fit the whole diagram with 16px padding at any zoom. Low zoom: less detail, larger titles, boundary
    labels: name only.
  - Oversized templates (Multi-cloud platform, Collaborative editor) show a cover: about 13 of their nodes at normal
    card scale.
  - Stage and template page use `readableViewport`: whole diagram if it fits at zoom 0.5, else a crop around the most
    connected node and its neighbours.
  - Cards play their first flow on hover or focus.
- **Editor:** canvas fills the space under the bar. With Flows open, the log pane docks below: transport row, sticky
  28px column header, 24px rows. Floating canvas chrome (zoom, hints, selection tools): chrome fill, hairline, 8px
  corners, 12px inset.
- **Present:** full-screen canvas. Top bar docks top, fades after idle during playback; caption strip docks bottom.
  Playback starts after 700ms, unless reduced motion. Previous, Next and arrow keys move one step, also onto connection
  steps (paused token partway along). "Step n of N" beside the scrubber from 640px.

Spacing: 4px step. 4px between toolbar items; 8px and 12px in panels and cards; 16px grid gaps and card side padding;
24px page side padding from 640px.

### Motion

- Flow camera: 1000ms position and 1600ms zoom windows; max 1.35 zoom ratio per step; within diagram bounds plus 48px.
- Reduced motion: camera cuts to each step; library stage waits for Play.
- Between edges at different points of one node, the token follows its outline.
- After manual pan or zoom, the camera hands back over 700ms.
- Node drops glide to the 16px grid in 140ms; colour changes ease over 160–200ms.

## Elevation & Depth

Flat: depth is tone (ground, chrome, raised, node fill). No shadow on docked panels; no shadow or backdrop-filter
on canvas nodes.

### Shadow Vocabulary

- **Menu lift** (`box-shadow: 0 12px 32px -12px rgb(0 0 0 / 0.45)` on the insert menu; shadcn popovers and menus:
  medium shadow plus 1px ring at 10% text colour): floating menus, popovers, dialogs; the only ambient shadow.
- **Knockout ring** (`box-shadow: 0 0 0 2px <ground>`): token dots, token chips, ports, to cut through lines.
- **Active ring** (`box-shadow: 0 0 0 1px <signal>`): doubles the border of an active or hovered node.

### Named Rules

**The Fill Not Outline Rule.** Nodes separate from the ground by fill; the hairline outline never does it alone.

**The Tone Not Opacity Rule.** Elements the flow has not reached: ground fill, dim outline, faint text, grey official
icons. No fading.

**The One Focus Rule.** Keyboard focus: one 2px Signal Blue outline, offset 2px (6px on canvas nodes). Text fields:
Signal Blue border.

## Shapes

Corner radii by size: 1px status squares; 2px handles; 3px edge-label knockouts; 4px badges, caption step; 5px token
chip; 6px cards; 8px buttons, inputs, menus, floating chrome (`0.5rem` radius token); 12px library cards, dialogs;
16px featured stage, runtime boundaries.

Node kind silhouettes:

- **Service:** 6px rectangle.
- **Datastore:** cylinder, 9px raised elliptical cap.
- **Queue or stream:** capsule (14px / 50%), ruled ribs, raised end cap.
- **Client:** rectangle, 6px raised title strip.
- **External system:** dashed Strong Line outline on ground fill.
- **Function:** 28px pill.

Status marker shapes: ok square, warn diamond, error circle.

App mark: text-colour square, 6px corners; right-angled rounded ground-colour wire; Signal Blue token at its start.

- 14px muted line icon (official cloud icons 16px, own colours), title, optional muted detail lines; `{braces}` lift a
  word to text colour.
- **Zoomed out:** icon at least 10px on screen, up to 36px, grows around its centre; title moves right, card size stays.
- **Active or hovered:** Node Fill Active, Signal Blue border and 1px ring.
- **Idle in a flow:** ground fill, dim outline, faint text, grey icons.
- **Selected:** 1px dashed text-colour outline offset 4px; 8px handles with 2px corners on hover.
- **Coloured:** neutral by default. A boundary-palette hue mixes 12% into Node Fill (8% light), 50% into the outline
  (45% light); caps 18% into Canvas Raised. Line icon and meter fill take the hue; title stays text colour. External
  cards: 6% into ground. Active, hovered and idle states override colour. Shapes: same mixes; Line shapes outline in
  full hue.

### Edges and labels

- Default routing `smooth` (right-angled, rounded); 1.25px round-capped stroke, Edge grey or protocol wire colour;
  dashed 5 4 and dotted variants.
- Diagram switch "Route connections around nodes" (default off): `smooth` and `step` edges avoid every node between
  their ends, 20px clearance, 12px apart in shared channels, reroute during node drag.
- Switch on: selected `smooth` or `step` edges in the editor get a 12px handle per middle segment (ground-coloured ring
  in selection colour, filled on hover, axis resize cursor). Dragging sets the route by hand; properties panel: "Route
  set by hand." and Reset route button.
- Labels: 11px mono knockouts on the ground, 4px side padding, muted or protocol text colour; hidden while the token
  passes.
- Visited and active edges: 2px, protocol text colour, or Signal Blue without protocol. Idle edges in a flow: Node Line.

### Walkthrough token (signature)

A 10px dot or 11px mono chip (5px corners, 2px 7px padding), ground-colour ring. Signal Blue until the first protocol
hop, then its current or last hop's protocol text colour; Wire Ink text. The chip lifts above a node it rests on,
fades near edge ends.

### Boundary (signature)

A group is a boundary with a kind: AWS, Azure, Google Cloud, Kubernetes, general (system boundary, environment, trust
boundary, data center, on-premises, team, application) or custom.

- **Line per tier** (SVG stroke, boundary hue; 1px, 8px corners unless noted):
  - Scope (organisation, account, subscription, project, tenant, system): solid 1.25px, 6px corners.
  - Runtime (cluster, node pool, Auto Scaling group, application): solid 1.25px, 16px corners; ground fill with canvas
    grid, covers lines of boundaries under it.
  - Logical (resource group, namespace, environment, team): dashed 8 5.
  - Location (region, data center, on-premises): dashed 16 6.
  - Zone (availability zone): 2px round dots, 5px pitch.
  - Network (VPC, virtual network): dash-dot 14 4 2 4.
  - Subnet: dashed 4 3.
  - Security (security group, trust boundary): dash-dot-dot 10 3 2 3 2 3, 1.25px.
  - Custom (Line field): dashed 6 4, solid or none.
- **Tinted area:** 5% hue wash (4% light); default on only for scope, network, subnet, runtime, custom.
- **Label:** knocked out of the top edge on the ground, 12px from left, 6px side padding, 6px gaps: 12px hue line icon
  (or 14px official group icon or logo), hue kind tag at 500, name in text colour at 500, optional muted mono detail
  ("10.0.0.0/16", "eu-west-1"). Custom groups: no kind tag. Empty name: "Group" placeholder, editor only.
- **Zoomed out:** label icon as on cards, up to 30px.
- **Kind tag text:** provider prefix (AWS, Azure, GCP, Kubernetes) plus sentence-case kind name; acronyms and proper
  names keep case ("AWS VPC", "AWS Auto Scaling group").
- **Colours off:** Strong Line outlines; muted kind tags and icons. Line patterns stay.
- **Selected:** as nodes.
- **Active in a flow or hovered from the log:** Signal Blue outline, 2px.

### Caption strip

Present, library stage and video export only. Docked to the canvas bottom, 48px to 72px, chrome fill, Node Line top
border: Signal Blue mono step badge, element at 500, event in mono (warn and error in level colour), caption muted.

## Do's and Don'ts

### Do:

- **Do** keep nodes neutral, set apart by fill (dark: #1F1F1F on #000) with quiet outlines; colour only marks groups
  (team, part kind).
- **Do** route new edges `smooth` (right angles, rounded corners), not bezier; colour wires by protocol, tokens by
  current or last hop.
- **Do** reserve Signal Blue for walkthrough, focus, caret, selection tint, the mark.
- **Do** set copyable values in Fragment Mono, slashed zero, tabular figures.
- **Do** mark boundary tiers by line pattern; boundary colours can be off.
- **Do** show previews as live read-only canvases, no grid; cards fit the diagram (or a large template's cover), stage
  uses `readableViewport`.
- **Do** give each new token a light-theme counterpart.
- **Do** stop autoplay and cut the camera under reduced motion.

### Don't:

- **Don't** use `backdrop-filter` on canvas nodes or edges.
- **Don't** add saturated blue to boundary or protocol palettes, amber to HTTP, or ok/warn/error colours to info events,
  decoration or node kinds.
- **Don't** shadow docked panels or canvas nodes; only the menu lift casts ambient shadow.
- **Don't** fade idle elements with opacity; use tone.
- **Don't** exceed weight 500 or uppercase interface labels.
